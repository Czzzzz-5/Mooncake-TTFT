# 实验卡：v1 验证（SLOT_MB=192）—— 三轮 A/B 对照

日期：2026-09-16　操作人：wuzichun（数据命令由本人手动执行）

## 设计

**三轮 A/B 对照**，每轮：同一台安静机器、同一 seed，唯一变量是
`MC_TCP_GPU_STAGING` 开关。不拿旧基线（406.63ms，含第三方负载）参与对比。

- **A 组**：`MC_TCP_GPU_STAGING=0`，legacy 路径（1760 次同步小拷贝）
- **B 组**：`MC_TCP_GPU_STAGING_SLOT_MB=192, SLOTS=4`，锁页池全开

## 环境

- 每轮开始前清场（杀旧进程、确认端口/GPU 释放）；14:00-14:45 期间整机安静
  （无其他用户登录，GPU 无外人任务）。
- GPU0 驱动问题已恢复，三块 5090 正常。

## 结果总表（每轮 4×16000 字符, ~2670 tokens/prompt）

| 轮 | seed | A: legacy TTFT avg | B: v1 TTFT avg | Δ | Δ% |
|---|---|---|---|---|---|
| 1 | 777 | 427.48 ms | 352.43 ms | **−75.0** | −17.6% |
| 2 | 888 | 406.61 ms | 359.28 ms | **−47.3** | −11.6% |
| 3 | 123 | 394.23 ms | 353.87 ms | **−40.4** | −10.2% |

**三个 seed 全部 B < A，平均收益 −54ms（−13%）。结论已跨 prompt 复现。**

逐请求形态：B 组每轮呈 ~300/~410ms 双模 2/2 分裂（如 seed888: 310/413/299/415）。
⚠️ 修正（2026-09-16 晚复核）：**A 组同样存在快慢分裂**（每轮一个 ~330-345ms +
三个 ~390-480ms），说明主因是 prefill 调度分批而非传输层排队——它是 A/B
公共项，差分中自动抵消，不影响 −54ms 结论；但提示 TTFT 中存在 ~100ms
量级的调度开销，优先用 parse_ttft.py 拆段定位。
另：两次同 config 的 A 组读数 427/407/394 也有 ±20ms 涨落，
再次印证"跨天单次读数不可信，只有同轮 A/B 差值有意义"。

## 生效证据（每轮 B 组均核验）

- [x] 两端 `GpuStagingPool: 4 x 201326592 bytes pinned slots ready`
- [x] 无 `exceeds slot capacity` / `all slots busy` WARNING
- [x] `pulling kv_caches finished` = 5（warmup+4），`failed transfers/recv = 0`
- [x] 原始档：`results/raw/{A,B}{1,2,3}_seed*.txt`

⚠️ 引擎侧 `Avg xfer time` 指标在本实验中噪声极大（窗口截断 + 双模拉偏），
B 组窗口均值 114~174ms 与 TTFT 改善方向矛盾时**以客户端 TTFT 为准**；
下轮实验改用日志时间戳/parse_ttft.py 逐笔拆解传输段。

## 结论

- **v1 真实生效，收益 −40~−75ms（三轮回平均 −54ms / −13%）**，焊死。
- 收益构成：传输自身变快（消除 pageable 税 + 单次拷贝）+ 不再用
  legacy 默认流同步拷贝切碎并发 prefill 计算（连带收益）。
- **下一步：v2 多槽流水**。动机在本轮已被数据预演：B 组双模交替说明
  并发传输在"拷完再发 + 单 io 线程"结构下互相排队，流水化 + 细粒度
  切片正是对症的。
- 遗留：① xfer time 指标口径需修（逐笔拆解）；② `cudaStreamPerThread`
  隐患未验证；③ v2 前值得用 `mooncake_tcp_bench.py --buf gpu` 做纯传输
  层 A/B（无 vLLM 干扰，直接量 115MB 单笔延迟）。
